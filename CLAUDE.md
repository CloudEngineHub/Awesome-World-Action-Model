# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

An **"awesome list"** — a curated, auto-updated catalog of research papers on World Action Models (WAM), Vision-Language-Action (VLA) models, and Embodied AI. The deliverable is documentation (`README.md` + `docs/*.md`), not an application. A small Python pipeline keeps part of the README in sync with arXiv. There is no build step and no test suite.

## Commands

```bash
pip install -r requirements.txt           # one-time setup

# Fetch latest papers from arXiv → writes data/papers.json + docs/latest-papers.md
python scripts/arxiv_scraper.py --max-results 50 --days-back 30

# Regenerate the "🆕 Latest Papers" section of README.md from data/papers.json
python scripts/update_readme.py
```

Run the two scripts in that order — `update_readme.py` consumes whatever `arxiv_scraper.py` left in `data/papers.json`. This is exactly what `.github/workflows/update-papers.yml` does on a daily cron (00:00 UTC) and on every push to `main`.

## Architecture: the auto-update pipeline

The core data flow is a one-directional pipeline with `data/papers.json` as the contract between the two stages:

```
arxiv_scraper.py ──writes──> data/papers.json ──read by──> update_readme.py ──rewrites──> README.md
                  └─writes──> docs/latest-papers.md
```

- **`scripts/arxiv_scraper.py`** (`ArxivScraperStrict`): runs a fixed set of title-anchored arXiv queries, then applies **strict keyword filtering** (keywords must appear in the *title*, except policy/world-model context which may match the summary). Papers that don't match are dropped (`auto_category == 'Other'` → excluded). Each kept paper is classified into exactly one of `VLA`, `World Model`, or `Policy` via `classify_paper()`. Output is sorted newest-first and written as JSON + a standalone markdown table.
- **`scripts/update_readme.py`**: loads `data/papers.json`, buckets papers by their `auto_category`, and **replaces the README section** matched by the regex `## 🆕 Latest Papers.*?(?=\n## |$)`. Everything between that heading and the next `## ` heading is machine-generated.

### Things that will bite you

- **Do not hand-edit the "🆕 Latest Papers" section of `README.md`.** It is regenerated wholesale by `update_readme.py` and your edits will be overwritten on the next run. Everything *else* in the README (Overview, the curated category tables like "VLA Models" / "World Action Models", Resources) is **hand-maintained** and the pipeline never touches it.
- **Two mismatched category vocabularies.** The scraper only ever emits `VLA` / `World Model` / `Policy`, but `update_readme.py`'s `categorize_papers()` defines extra buckets (`Robotics`, `Action Learning`, `Reasoning`, `Simulation`). Any `auto_category` not in that dict falls through to `Other` (this defensiveness was the fix in commit `5f2a868`). If you add a category in one script, update the other.
- **`scripts/add_papers.py` is currently broken.** It does `from arxiv_scraper import ArxivScraper`, but the class is named `ArxivScraperStrict`, and it calls `search_papers()` / `classify_paper()` with the wrong signatures. Fix the import and call sites before relying on it.
- **`.github/metrics.json` is hand-maintained.** Nothing in the pipeline writes it, so its `updated` date and `papers_count` drift out of sync with the actual README. The README's "Last update" badge reads from this file — update it manually when relevant.

## Data & docs layout

- `data/papers.json` — **the live input** to `update_readme.py` (currently ~50 recent papers). This is the only data file the pipeline reads.
- `data/papers_extended.json`, `data/additional_papers.json` — larger curated collections (the ~129-paper corpus behind `docs/all-papers.md`); **not** consumed by the automated pipeline.
- `docs/all-papers.md` — full curated paper list. `docs/baselines.md` — baseline methods extracted from paper experiment tables. `docs/latest-papers.md` — generated by `arxiv_scraper.py`.

A paper object's key fields: `id`, `title`, `authors` (list), `summary`, `published` (`YYYY-MM-DD`), `url`, `code_url`, `project_url`, and `auto_category` (the classification the README generator keys on).
